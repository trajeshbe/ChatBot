## Architecture Overview

The KIAA Intelligence Suite Dashboard is built on a modular, microservices-based architecture that provides a centralized access point to multiple AI-powered intelligent modules. The architecture is designed for scalability, maintainability, and extensibility.

## Component Architecture

### 1. Dashboard Layer (Presentation Tier)

#### Technology Stack
- **Framework**: Streamlit
- **Language**: Python 3.x
- **UI Rendering**: HTML/CSS (generated by Streamlit)
- **State Management**: Streamlit session state

#### Core Components

**a. Main Application Class (`MainAPP`)**
```python
class MainAPP:
    - __init__(): Initialize dashboard, set configuration
    - render_card(): Render individual module cards
    - render_main_ui(): Orchestrate overall UI layout
```

**Key Features**:
- Page configuration with wide layout
- Custom styling with HTML/CSS injection
- Dynamic card rendering from JSON configuration
- Responsive 3-column grid layout
- External link navigation

**Configuration File**:
- **File**: `app_info.json`
- **Purpose**: Centralized module metadata
- **Structure**:
```json
{
  "Topic": "Category Name",
  "Description": "Category description",
  "sub_topic": [
    {
      "title": "Module Name",
      "link": "http://host:port/",
      "desc": "Module description",
      "env": "/path/to/python/env",
      "path": "/path/to/module/script.py"
    }
  ]
}
```

### 2. Microservices Architecture

#### Service Organization

The system implements a distributed microservices architecture where each AI module runs as an independent service:

**Service Characteristics**:
- **Independence**: Each module operates autonomously
- **Isolation**: Separate Python environments per module
- **Scalability**: Individual modules can scale independently
- **Resilience**: Failure in one module doesn't affect others

## Technical Constraints & Limitations

### Current Limitations

1. **No Authentication**: Open access to all modules
2. **HTTP Only**: Unencrypted communication
3. **Single Server**: No redundancy or failover
4. **Manual Deployment**: No automated CI/CD
5. **No Centralized Logging**: Distributed logs across modules
6. **Limited Monitoring**: No comprehensive observability
7. **Stateless Modules**: No session persistence across requests

### Scalability Constraints

1. **Shared Resources**: All modules on single server
2. **Port Exhaustion**: Limited to available ports
3. **Memory Constraints**: Competing for system RAM
4. **Process Isolation**: No containerization
